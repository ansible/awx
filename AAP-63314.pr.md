# [AAP-63314] P4.4: Controller - Pass Workload TTL to Gateway

## SUMMARY

Passes `job.timeout` as `workload_ttl_seconds` when Controller requests a workload identity JWT from Gateway, enabling the Gateway to issue JWTs with TTLs matched to the job's expected runtime.

**This is the final link in the P4 TTL chain:**

```
job.timeout (Controller)
    → workload_ttl_seconds in POST /api/gateway/v1/workload_identity_tokens (DAB client)
        → two-priority TTL calculation (Gateway, AAP-63312)
            → JWT exp = workload duration + 60s clock skew
```

**Design decisions:**

1. **Source:** Uses `instance.timeout` directly — this reflects the effective job timeout (from job template, or 0 if not set)
2. **Zero handling:** `job.timeout = 0` sends `workload_ttl_seconds=None`, signaling Gateway to use platform default (`jwt_default_ttl_seconds`). Zero is no longer a valid value in the DAB serializer (`min_value=1`); `None` is the correct sentinel.
3. **Ceiling cap:** `job.timeout` is capped at `WORKLOAD_TTL_MAX_SECONDS` (imported from DAB) before being sent. This prevents jobs with very long or unlimited timeouts from causing a 400 from the Gateway serializer's `max_value=86400` constraint.
4. **No fallback logic here:** TTL priority and platform fallback are handled by the Gateway (AAP-63312) — Controller's only responsibility is to pass the value
